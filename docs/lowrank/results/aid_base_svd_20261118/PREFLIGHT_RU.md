## SSD и потребность в месте

По `lsblk`, `findmnt`, `df -B1` и `df -i` рабочий каталог, AID, артефакты, Docker, системные `/tmp` и `/var/tmp` расположены на одном ext4-разделе `/dev/nvme0n1p5` накопителя ADATA LEGEND 710 (NVMe, ROTA=0). Ёмкость ФС 474 453 426 176 байт. Начальный доступный пользователю объём по statvfs — 4 605 988 864 байта, свободно 27 566 032 inode из 29 491 200. Раздел занят на 99% по df. Доступное пользователю пространство уже учитывает резерв ext4.

Docker сообщает `overlay2`, корень `/var/lib/docker`. Рабочая копия монтируется в контейнер как `/workspace`. Временные NPZ создаются рядом с целевым файлом. Контейнерный `/tmp` относится к записываемому слою Docker, `/dev/shm` — tmpfs. Хостовый TMPDIR не задан. Кэш проекта занимает 1 325 268 992 байта, AID — 2 742 579 200. Повторная загрузка весов и копирование AID для этой серии не требуются. По docker system df образы занимают 65,25 GB, контейнеры 3,176 GB, volumes 1,206 GB, build cache 0. Эти категории используют общие слои и не прибавляются к свободному пространству.

## GPU и RAM

Хост подтвердил RTX 4070, 12 282 MiB VRAM, занято 157 MiB, вычислительных процессов при проверке не было. RAM 66 491 039 744 байта, доступно 59 718 311 936. Драйвер 555.42.02 указывает совместимость CUDA 12.5. В контейнере JAX и jaxlib 0.4.38, пакет CUDA runtime 12.9.79. JAX обнаружил cuda:0.

Параметры, градиент и два FP32-момента AdamW для dense в сумме дают 1 373 147 616 байт. Для ориентира, QKV, матрица attention scores и скрытое состояние MLP в одном блоке требуют суммарно 6 099 120 байт на изображение (97 585 920 при batch 16). При хранении этих тензоров всех 12 блоков на backward при batch 8 получается 585 515 520 байт. Эти частичные суммы исключают другие активации, временные буферы, особенности fusion, копии обновлений, XLA и аллокатор. Фактическая вместимость batch 1/16 и FT batch 8 требует smoke-проверки. Compilation, latency и inference peak Base пока не измерены.

## Возобновление

Ветка `research/lowrank-vit-base-20261118`. В этой серии готова только предпусковая проверка. Для первой попытки в том же checkout запустить следующий блок из корня репозитория. Он проверяет исходные SHA и место до первого обращения к GPU. При смене раздела или пути Docker сначала пересчитать свободное место и резерв на каждом затронутом разделе.

```bash
(
  set -eu
  S=artifacts/experiments/aid_base_svd_20261118
  F=artifacts/experiments/aid_base_final_20261118
  C=configs/aid_vit_base.yaml
  W=artifacts/checkpoints/jax/vit_base.npz
  df -B1 --output=source,avail,iavail,target artifacts data/AID /var/lib/docker /tmp
  test "$(df -B1 --output=avail artifacts | tail -1)" -ge 220581609472
  sha256sum -c <<'SHA'
a93c5cf00c34b25212a81fcee07432024731a9932f071cf6ccf9dba1ec7c30e4  artifacts/checkpoints/jax/vit_base.npz
af13adab243c8c99650d7944cc5ff0ac636f6ed50ab0b45d2fd714f089982e44  runs/aid_vit_base/best.pt
461095915d1fd9713b12485671eba7dd21004af80dbbb11e88985891b309e57e  runs/aid_split_seed42.json
6dc908691346cda7fb77423b506320d2a60bae63f5d01135bf79ea9ef99a523c  configs/aid_vit_base.yaml
SHA
  export AERIAL_SVD_MIN_FREE_BYTES=34359738368
  # Изолированный smoke на validation. При повторной попытке указать новый каталог.
  scripts/run.sh gpu python -m aerial_svd.lowrank_benchmark \
    --config "$C" --checkpoint "$W" --device gpu --batch-sizes 1 16 \
    --warmup 1 --repeats 2 --output-dir "$F/00_resource_smoke/dense-b1-b16"
  python3 scripts/lowrank_series.py --series setup --root "$S" \
    --config "$C" --checkpoint "$W" --expected-top1 0.9713333333333334
)
```

Для следующих стадий также экспортировать `AERIAL_SVD_MIN_FREE_BYTES=34359738368` (24 GiB резерва + 8 GiB на запуск). Каждая новая контейнерная стадия проверяет этот порог. Перед продолжением частичного прогона сверить manifests и ещё требуемый объём. Отдельно проверить один шаг факторизованной FT с batch 8 до запуска обучения всей серии. Дальнейшие корни — `aid_base_activation_20261118` и `aid_base_final_20261118`. Каждому вызову перечислителя ordinary **и** activation передавать Base `--config` и `--checkpoint`. Для итогового отчёта использовать реально завершённый каталог агрегирования. Имена Small в примерах руководств относятся к исторической серии.
